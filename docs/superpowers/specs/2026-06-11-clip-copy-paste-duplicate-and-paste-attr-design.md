# Clip copy/paste, duplicate, and Paste Attributes

_Tournament-selected 2026-06-11. Effort ~4 engineer-days._

## Spec

Add a transient in-memory clipboard to the zustand timeline store (src/renderer/state/timeline-store.ts): `copySelection()` snapshots each selected clip from `selection.clipIds` (resolved against `sequence.spine` and `sequence.connected`) into a payload of `{assetId, mediaInFlicks, durationFlicks, sourceDurationFlicks, fx?, titleData?, lane?, relOffsetFlicks}` ordered by derived start (`spineStartOf`/`connectedStartOf`), with relOffsetFlicks relative to the earliest copied clip. `pasteAtPlayhead(mode: 'insert' | 'connect')` wraps the whole paste in `stack.beginGroup()/endGroup()` (one undo step, exactly like `deleteRanges`) and replays the payload through existing kernel ops: `insertAt` for spine clips at playhead + accumulated duration (ClipInput is `Omit<Clip,'kind'>` so `fx` already rides along), and `connectAt` for connected/title clips at playhead + relOffset — one small kernel fix needed because `connectAt` in src/shared/timeline/ops.ts currently drops `args.clip.fx` when constructing the ConnectedClip. New ids come from `crypto.randomUUID()` as in `clipInputFrom`, so the kernel's duplicate-id validation never trips. Paste Attributes adds a pure `mergeFx(target: ClipFx, source: ClipFx, cats: {transform; color; audio})` helper in ops.ts (transform = posX/posY/scale/rotation/opacity; color = exposure/contrast/saturation/temperature; audio = volumeDb/pan/fadeIn/fadeOut from the existing ClipFx blob in model.ts) and a store action `pasteAttributes(cats)` that applies grouped `setClipFx` calls — which already accepts both spine and connected ids — onto every selected clip using the clipboard's first fx, defaulting absent target fx from `DEFAULT_FX`. UI surface: register `ctrl+c`, `ctrl+v`, `alt+v` (paste connected), and `ctrl+shift+v` in TimelinePanel.tsx's existing `registerShortcut` block; add Copy / Paste / Paste Attributes items to the canvas context menu in TimelineCanvas.tsx `onContextMenu` (the new ContextMenu component with `data-testid="context-*"` makes this trivial); and a small PasteAttributesDialog.tsx modal with three checkboxes + Paste button styled like the existing panels. Crucially, Ctrl+C/Ctrl+V are swallowed by the native `role: 'copy'/'paste'` menu items in src/main/menu.ts before the renderer keydown fires, so those roles are replaced with custom items that send the existing `IPC.editCommand` channel (extended union 'undo'|'redo'|'copy'|'paste'|'pasteAttributes' in src/shared/ipc.ts + preload), and the renderer handler in TimelinePanel falls back to `document.execCommand` when `isEditableTarget(document.activeElement)` so text fields keep native copy/paste. Alt-drag duplicate extends the existing 'move' drag mode in TimelineCanvas.tsx: record `altKey` in DragState at pointerdown, and on pointerup apply `insertAt` with a fresh-id copy of the dragged clip at the ghost boundary instead of `moveClip`. No persistence or data-model changes: clipboard is session-only, ClipFx/TitleData already serialize per clip in the project JSON, and `resolveLaneCollisions`/`reattachByTime` keep connected-clip invariants on paste. Unit tests go in ops.test.ts (connectAt fx carry, mergeFx categories) plus store-level paste tests; everything else is exercised through the keyboard-driven E2E below.

## E2E plan

New e2e/clipboard.spec.ts following timeline.spec.ts conventions: launch with MAGNETIC_TEST + temp MAGNETIC_LIBRARY_PATH, importPaths a fixture, press 'e' twice to append two clips, read state via __magneticState(). (1) Copy/paste: click clip 1 on the canvas at xForTime to select, Ctrl+C, End, Ctrl+V; assert spine length 3 and the new clip matches the source's assetId/mediaInFlicks/durationFlicks with a distinct id; Ctrl+Z removes it in one step. (2) Paste connected: Alt+V at a mid-sequence playhead, assert sequence.connected gained a clip on lane 1. (3) Paste Attributes: set fx on clip 1 through the store/inspector, Ctrl+C, additive-click clips 2 and 3, Ctrl+Shift+V, assert getByTestId paste-attributes dialog visible, uncheck Audio, click Paste; assert both targets' fx have the source transform/color values but DEFAULT_FX audio values, and a single Ctrl+Z reverts both (grouped undo). (4) Alt-drag duplicate: mouse.down on clip 1 body with Alt, drag past DRAG_THRESHOLD_PX to the end boundary, release; assert spine grew by one with duplicated media fields. Keyboard-driven and state-asserted via the existing test hooks, so no canvas-pixel fragility.

## Risks

Main risk is the native menu accelerator swallow: Electron's role:'copy'/'paste' items consume Ctrl+C/Ctrl+V before renderer keydown, so the menu items must be converted to IPC editCommand senders with an isEditableTarget fallback to keep text-field copy/paste working — the undo/redo precedent in menu.ts proves the pattern but the text-input fallback needs care (execCommand or webContents.copy/paste routing). connectAt currently drops fx, so pasted connected clips would silently lose grades without the kernel fix. Paste semantics when the playhead sits mid-clip rely on insertAt's ensureBoundary splitting (correct FCP insert behavior, but worth an explicit test for the sub-frame snap path). Alt-drag duplicate touches the densest interaction code in TimelineCanvas (per electron-canvas-e2e-gotchas memory, no synthetic pointermove in Electron e2e — use mouse.move with steps). Multi-clip spine+connected mixed copies can produce surprising parenting after paste since connectAt reparents by time; acceptable, matches the magnetic model, but document it. No persistence-format or playback-engine risk: clipboard is session-only and all mutations reuse existing undoable ops.
