# Keyframe animation of video parameters

_Tournament-selected 2026-06-11. Effort ~5 engineer-days._

## Spec

Extend ClipFx (src/shared/timeline/model.ts) with an optional `kf?: Partial<Record<AnimatableParam, Keyframe[]>>` where AnimatableParam is the 9 video/color scalars (posX, posY, scale, rotation, opacity, exposure, contrast, saturation, temperature) and Keyframe = { atMediaFlicks: number; value: number; ease: 'linear' | 'easeInOut' }, sorted by time. Keyframes are anchored in MEDIA time (same basis as `mediaInFlicks`), so blade, trim, ripple, and rearrange need zero kernel changes — both blade halves inherit the same fx object and each evaluates only its own media window; values hold (clamp) outside the first/last keyframe. Add a new pure module src/shared/timeline/fx-eval.ts exporting `evaluateFxAt(fx: ClipFx | undefined, mediaFlicks: number): ClipFx` that returns the static scalar for un-keyframed params and the eased interpolation (easeInOut = smoothstep on the segment) for keyframed ones; this is the single evaluation function shared by preview and export. No new ops or undo work: keyframe add/move/delete builds a new ClipFx and calls the existing `setClipFx` op (ops.ts:438) via `useTimelineStore.setFx` (timeline-store.ts:187), which already yields one undo step with a restore inverse. Playback: in PlaybackEngine.assembleLayers and titleLayer (engine.ts:428/310, which already receive tSec and know item.mediaInSec/startSec), replace `fx: item.fx` with `fx: evaluateFxAt(item.fx, (item.mediaInSec + (tSec - item.startSec)) * FLICKS_PER_SECOND)` — the Compositor (compositor.ts) keeps receiving a plain resolved ClipFx and needs no changes, and exportReplay/renderStill flow through the same assembleLayers, so export is WYSIWYG for free. Inspector (InspectorPanel.tsx): each FieldDef row in the video and color tabs gains a diamond toggle button (data-testid `kf-toggle-${key}`) plus prev/next-keyframe arrows; with keyframes present, the number input shows the evaluated value at the playhead and editing it writes/updates a keyframe at the playhead's media time (playheadFlicks minus spineStartOf/connectedStartOf, plus mediaInFlicks); toggling off strips the track and freezes the current evaluated value as the static scalar. Timeline: drawTimeline in src/renderer/timeline/render.ts paints small diamonds along the bottom edge of any clip rect whose fx.kf is non-empty, positioned at (keyframe media time − mediaInFlicks) converted to px — display-only in v1, no canvas drag editing (the inspector is the editing surface, dodging the known no-synthetic-pointermove Electron E2E gotcha). Audio params (volumeDb, pan, fades) stay static — gain automation already exists in playback/automation.ts. Persistence is free: sequences serialize ClipFx as-is and the field is optional, so old libraries load unchanged.

## E2E plan

Follow the effects.spec.ts pattern exactly: launch out/main/index.js with MAGNETIC_TEST + temp MAGNETIC_LIBRARY_PATH, importPaths the green-prores fixture, append it to the spine via the existing store hooks. Pixel proof of animation: set fx with scale keyframes {0s: 100, 4s: 40} via the inspector UI (fill data-testid fx-scale after clicking kf-toggle-scale at two playhead positions), then setPlayhead to t=0 and t=4s, await renderStill settle, and sampleRgb via __magneticTimeline.playback.readPixels at a corner point (~150,150): green at full scale, black letterbox at 40% — and at t=2s assert an intermediate state (corner black but a point at ~600,350 still green) proving interpolation, not a step. Repeat once for opacity (center brightness high at t=0, near-black at keyframed 0%). Undo proof: ctrl+z then assert via __magneticState() that the kf track reverted. Export WYSIWYG proof rides the existing export spec path (exportReplay shares assembleLayers), so a single ffprobe-frame brightness check at two timestamps in the exported mp4 is optional belt-and-braces.

## Risks

1) Keyframe time basis: media-time anchoring makes blade/trim free, but `slip` (ops.ts:405) moves content under the keyframes — keyframes stay glued to source media, which is defensible but differs from FCP's clip-relative behavior; decide and document. 2) Whole-fx-object undo granularity: every inspector keystroke is currently one undo step via setClipFx; dragging a value with keyframes on will spam the undo stack the same way static fx already does (pre-existing behavior, not worsened, but more noticeable when sculpting curves). 3) titleLayer caches the rendered canvas by JSON hash of TitleData only — opacity keyframes on titles work (opacity is applied as a uniform, not baked), but verify the bumper preset's baked 0.5s fade multiplies correctly with a keyframed opacity. 4) Paused-still refresh: inspector edits must retrigger renderStill (works today for static fx — confirm the store subscription fires on kf-only changes since the sequence object identity changes; it does, setClipFx returns a new sequence). 5) Timeline diamond markers add per-clip draw work in the 2D canvas hot path measured by the perf harness (measureDraws) — keep markers to a cheap loop and skip when zoomed out below ~20px/clip. 6) No curve editor or canvas-side keyframe dragging in v1 — scope creep pressure toward an FCP-style video animation editor should be resisted; the inspector + markers covers punch-in/Ken Burns/PiP use cases.
