# Expand/detach audio + split edits (J-cuts / L-cuts)

_Tournament-selected 2026-06-11. Effort ~4 engineer-days._

## Spec

Add an optional `audioDisabled?: boolean` to `Clip` in src/shared/timeline/model.ts (backward-compatible JSON; no migration). Add two kernel ops in src/shared/timeline/ops.ts following the existing total-function `(seq, args) → OpResult` pattern: (1) `detachAudio(seq, { clipId })` — validates the id is a spine clip of kind 'clip' without `audioDisabled`, replaces it with `{ ...item, audioDisabled: true }`, and appends a `ConnectedClip` `{ id: uniqueId(ids, clipId+':audio'), assetId, parentClipId: clipId, offsetFlicks: 0, lane: -1, mediaInFlicks, durationFlicks, sourceDurationFlicks }`; `resolveLaneCollisions` (called inside the existing `ok()` helper) already bumps to −2 on overlap, and snapshot undo is free. (2) `trimConnected(seq, { clipId, edge, deltaFlicks })` — head: clamp delta to `[-mediaInFlicks, duration − flicksPerFrame]` and additionally so the derived absolute start (`connectedStartOf`) stays ≥ 0, then apply `offset += delta; mediaIn += delta; duration −= delta` (a negative head delta produces a negative `offsetFlicks` = the J-cut; `connectedStartOf`, `reattachByTime`, and the renderer all handle negative offsets, verified by reading them); tail: clamp duration to `[flicksPerFrame, sourceDuration − mediaIn]` (the L-cut). Playback/export: one line in `collectAudioJobs` (src/renderer/playback/audio-graph.ts) — skip spine clips with `audioDisabled`; connected lane −1 audio already plays via the existing connected-clip loop, video compositing already ignores `lane <= 0` (engine.ts `buildItems`), and offline export reuses `collectAudioJobs`, so WYSIWYG export works automatically. Store: add `detachAudio(clipId)` and `trimConnectedClip(clipId, edge, delta)` actions in timeline-store.ts wrapping `apply()`. UI surface: a "Detach Audio" item in the existing TimelineCanvas right-click ContextMenu (enabled only for spine clips whose asset has audio, e.g. `snapshot.assets[assetId].waveform !== undefined` or an audio flag on AssetView), plus a `ctrl+shift+s` binding registered via `registerShortcut` in src/renderer/layout/TimelinePanel.tsx acting on the selected spine clip (FCP parity). Trim interaction: extend TimelineCanvas hit-testing so connected-clip rects from `computeClipRects` get head/tail edge zones within the existing `EDGE_HIT_PX`, starting a new `'trim-connected'` DragState mode that reuses the existing trim ghost/snap/Escape-cancel machinery and commits `trimConnectedClip` on mouseup; hover shows the same col-resize cursor + edge bracket at `laneY(cc.lane)`. Detached audio composes with everything already built: it follows its parent on move/ripple (parentClipId + offset), reattaches by absolute time when the parent is deleted, carries ClipFx (volumeDb/pan/fades/automation) via the existing inspector path, and is selectable/lift-deletable like any connected clip.

## E2E plan

New e2e/split-edits.spec.ts following timeline.spec.ts conventions (electron.launch with MAGNETIC_TEST=1, importPaths fixture, __magneticState assertions, mouse — not pointer — events). Steps: import bars-1080p30.mp4 + a second clip, press 'e' twice; right-click the first spine clip on the canvas and click the DOM ContextMenu "Detach Audio" item (DOM menu avoids canvas-coordinate fragility); assert via __magneticState that spine[0].audioDisabled === true and connected has one clip with lane === -1, offsetFlicks === 0, matching mediaIn/duration. Then compute the audio clip's head-edge canvas position from state (rowLayout math mirrored in the spec like the existing xForTime helper — state-derived hit rects per the repo's E2E gotchas) and drag it left ~30px with page.mouse.down/move/up; assert offsetFlicks < 0, mediaIn decreased, duration increased by the same flicks (the J-cut), with the kernel state as ground truth. Verify audio truth via the existing test hooks: seek into the audio-lead region where only the detached audio is active, play, and poll __magneticTimeline.playback.rms() > threshold; pause and assert rms ≈ 0. Finally Ctrl+Z twice and assert the sequence deep-equals the pre-detach snapshot, then relaunch the app against the same library path and assert the detached state persisted.

## Risks

1) Negative offsetFlicks is a new regime — connectAt/splitInWorking/reattachByTime were all written for offset ≥ 0; splitInWorking's `offsetFlicks >= localFlicks` re-parent test behaves correctly for negative offsets (stays with head), but invariants.test.ts may assert offset ≥ 0 and need updating, and trimConnected must clamp the derived absolute start ≥ 0. 2) Canvas trim-handle E2E inherits the documented Electron friction (no synthetic pointermove, layout-shift races when lane count changes row heights — detaching adds an audio lane and moves spineY, so the spec must recompute geometry from state after every op). 3) Post-detach video/audio desync on parent head-trim/slip is inherent FCP behavior (that is the point of detach) but should be called out in docs/GUIDE.md so it isn't filed as a bug. 4) Blade does not cut connected clips, so blading a detached clip leaves one long audio clip under both halves — acceptable FCP-ish behavior, explicitly out of scope. 5) Lane collision bumping can push a second detached audio to lane −2, growing canvas height; rowLayout handles it but screenshots/E2E pixel assumptions elsewhere (final-screens.spec.ts) could shift if they ever detach audio — they don't today.
